# План развития Flower Shop

Репозиторий: <https://github.com/abdullo-yakubov/---Flower-Shop-> · единственная ветка — `main`.

## Сделано (2026-11-26)

### Заказы и цены

- Единый серверный расчёт в `PricingService`: размер или стебли (только из `StemOptions`), корзинка +80 с,
  праздничная наценка, **аддоны теперь входят в сумму** (раньше не учитывались), доставка, промокод, баллы.
- `POST /api/v1/orders/quote` — предварительный расчёт той же логикой, что и создание заказа.
- Создание заказа в одной транзакции; номер заказа под `pg_advisory_xact_lock` (раньше `COUNT+1` давал дубли).
- Списывается ровно столько баллов, сколько дало скидку (раньше списывался весь запрос, даже сверх лимита 30 %).
- Счётчик промокода растёт, только если промокод реально применён; фиксированная скидка не превышает сумму.
- Проверки: количество 1–20, размер принадлежит товару, упаковка доступна, товар в наличии, открытка/зона существуют.
- Отмена заказа возвращает баллы, снимает начисленные, уменьшает счётчик промокода и статистику клиента.
- Слоты доставки: бэкенд принимал только `09:00-12:00`, а фронт шлёт `09:00–12:00` — **любой заказ через API отклонялся**. Исправлено.
- Статусы в API — `photo_ready`/`courier_en_route` (раньше `photoready`, фронт их не распознавал).

### Фронтенд

- Цена в корзине теперь включает корзинку — суммы в мини-корзине и на чекауте совпадают.
- Дата доставки — локальная (раньше UTC: с 00:00 до 05:00 «сегодня» уходило вчерашним числом).
- При ошибке API «оптимистичный» заказ удаляется, показывается понятное сообщение сервера.
- Промокоды: проверка сроков действия и минимальной суммы; при включённом API — серверная проверка.
- Добавлен перевод `checkout.order_error` (ru/en/tg), убраны дубли констант доставки.

### Бренд

- Логотип-тюльпан (`shared/ui/Logo.tsx`) в шапке и подвале, новый `favicon.svg` вместо логотипа Vite.
- `theme-color` в фирменных цветах для светлой/тёмной темы, `description` и Open Graph.

### Безопасность и инфраструктура

- ImageSharp (high-severity CVE; 3.2+ требует платной лицензии) заменён на SkiaSharp (MIT); защита от `../` при удалении файлов.
- Rate limiting реально подключён (политики были объявлены, но не применялись) и считается по IP.
- Ошибки валидации — в едином формате `{ success:false, error:{ code, message, details } }`.
- Refresh-токен заблокированного пользователя отклоняется; OTP генерируется криптостойко.
- API не стартует без `Jwt:SecretKey` ≥ 32 символов; из docker-compose убран публичный ключ по умолчанию.
- Поиск товаров регистронезависимый (ILIKE), исправлены фильтры по типу цветов и упаковке, стабильная пагинация.
- CI перенесён в корень (из `flower-shop/.github` GitHub его не видел) + добавлен job для бэкенда; Renovate — в корень.
- Husky-хук теперь устанавливается из корня репозитория.
- Исправлен `check-bundle-size.mjs` (считал сырые размеры вместо gzip: реальный бандл 285 КБ при бюджете 350 КБ).
- Удалено лишнее: MinIO (не использовался), дубль docker-compose в `flower-shop-backend/`, неиспользуемые
  `UserRepository`/`OrderRepository`/`UnitOfWork`, шаблонные файлы Vite (`App.tsx`, `App.css`, `assets/*`, `icons.svg`),
  устаревший `TASK_IMAGES.md`, `FlowerShop.API.http` (weatherforecast), ветка `improvements`.
- Тесты: бэкенд 41 (xUnit: цены, промо, баллы, валидация, файлы), фронтенд 50 (vitest).
