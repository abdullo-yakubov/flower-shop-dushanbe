## 1. Общее описание проекта

Проект представляет собой веб-платформу для заказа и доставки цветов, состоящую из клиентского приложения и backend API:

1. **Клиентский интернет-магазин** (`flower-shop`) — публичная витрина каталога, корзина, оформление заказа, личный кабинет покупателя.
2. **REST API** (`flower-shop-backend/src/FlowerShop.API`) — бэкенд для клиентского приложения.
3. **База данных** PostgreSQL 16 и вспомогательные сервисы (хранилище файлов, SMS-провайдер).

Целевой рынок — Таджикистан (Душанбе): валюта — сомони, телефоны в формате `+992…`, локализация на 3 языка (русский, английский, таджикский), способы оплаты и зоны доставки заточены под город.

### 3.4 Функциональные требования (клиентская часть)

#### 3.4.1 Каталог товаров
- Список товаров с пагинацией/фильтрацией по: категории (повод — Occasion), типу цветов (Rose/Peony/Tulip/Orchid/Mixed), цвету, цене, наличию (`InStock`), доступности доставки сегодня (`DeliverToday`), метки «новинка» (`IsNew`) и «хит» (`IsHit`).
- Карточка товара в списке: фото, название (на активном языке), цена, старая цена/скидка, рейтинг, кол-во отзывов.
- Быстрый просмотр товара (Quick View) — модальное окно без перехода на страницу товара.
- «Недавно просмотренные» товары.

#### 3.4.2 Страница товара
- Галерея изображений товара (`ProductImage`, с сортировкой `SortOrder`).
- Выбор размера (`ProductSize`: S/M/L) — каждый размер может иметь свою цену, старую цену, отдельное изображение.
- Для товаров типа «поштучно» (`ProductKind.Single`) — выбор количества стеблей (`StemOptions`, цена за стебель `StemPrice`).
- Выбор упаковки (`Packaging`: с корзиной / без корзины).
- Состав букета (`CompositionRu/En/Tg`).
- Рейтинг и отзывы с фото.
- Добавление отзыва (только авторизованным пользователем).
- Добавление в корзину, добавление в избранное.
- Признак «доставка сегодня».

#### 3.4.3 Корзина
- Изменение количества, удаление позиций.
- Выбор дополнительных товаров (аддоны: открытки, шоколад, игрушки и т.п., с возможной надписью — `HasInscription`).
- Применение промокода (`% скидка`, фиксированная скидка, минимальная сумма заказа, ограничение по числу использований, срок действия).
- Списание бонусных баллов программы лояльности (в пределах максимального процента от суммы, см. `LoyaltyConstants.MaxRedeemPercent`).
- Автоматический пересчёт итоговой суммы с учётом праздничной наценки (см. 3.4.4).

#### 3.4.4 Оформление заказа (Checkout)
- Выбор адреса доставки (сохранённые адреса из личного кабинета либо новый адрес).
- Выбор зоны доставки (4 зоны — см. таблицу ниже), даты и временного слота доставки.
- Признак «подарок» (`IsGift`): данные получателя (имя, телефон), анонимность отправителя (`IsAnonymous`).
- Выбор открытки (`Postcard`) и текста поздравления (готовый шаблон `MessageTemplate` или свой текст `CardText`).
- Выбор способа оплаты: `Dc` (Душанбе Сити), `Alif`, `Cash` (наличными курьеру).
- Контактные данные покупателя (имя, телефон).
- Подтверждение и создание заказа — генерация номера заказа в формате `#000001`.

**Зоны доставки (`shared/config/deliveryConfig.ts`):**

| Зона | Стоимость | Время доставки |
|---|---|---|
| Центр | 30 сомони | 1–2 часа |
| Север | 40 сомони | 2–3 часа |
| Юг | 40 сомони | 2–3 часа |
| Пригород | 60 сомони | 3–5 часов |

Бесплатная доставка от порога суммы заказа (`MinFreeDelivery`, по умолчанию 1500 сомони).
Временные слоты доставки: 09:00–12:00, 12:00–15:00, 15:00–18:00, 18:00–21:00.

Праздничная наценка (`HolidayPricing`): настраиваемый % (по умолчанию 30%) на конкретные дни года, применяется либо только к живым цветам (`Freshness.Live`), либо ко всем товарам.

#### 3.4.5 Личный кабинет (Account)
- История заказов со статусами и историей их изменения (`OrderStatusHistory`, с возможным фото готового букета/факта доставки).
- Отмена заказа (если `IsCancellable`), с указанием причины.
- Избранные товары.
- Управление адресами доставки (добавление, редактирование, удаление, адрес «по умолчанию»).
- Программа лояльности: баланс баллов, накопленное всего, статус/тир (Bronze/Silver/Gold), история операций (начисление/списание).
- Профиль: имя, аватар (загрузка изображения).
- Управление своими отзывами.
- Управление push-подписками (Web Push API).

#### 3.4.6 Аутентификация покупателя
- Вход/регистрация по номеру телефона через одноразовый код (OTP) по SMS.
- Ограничения: не более 5 отправок кода в час на номер, не более 3 попыток ввода кода, срок действия кода — 10 минут.
- В mock-режиме (разработка) код всегда `123456`.
- Хранение токенов: access-токен (15 мин) — в `sessionStorage`/`localStorage`; refresh-токен (30 дней) — в `localStorage`.
- Автоматическое обновление access-токена по 401-ответу через axios-интерцептор; при неудаче — принудительный выход пользователя (событие `flower:session-expired`).

#### 3.4.7 Локализация (i18n)
- Три языка: русский (эталонный, источник TypeScript-типа переводов), английский, таджикский.
- Строгая типизация словарей — отсутствие ключа перевода приводит к ошибке компиляции.
- Выбор языка сохраняется в `localStorage`, обновляет атрибут `lang` документа.
- Домены переводов: `common, nav, header, home, catalog, occasions, product, cart, checkout, account, auth, loyalty, push, holiday, share, theme, footer, notfound`.

#### 3.4.8 Прочие UX-требования
- Тёмная / светлая / системная тема оформления.
- Мобильная нижняя навигация (Bottom Navigation Bar).
- Cookie-consent баннер.
- Анимация добавления товара в корзину («улёт» карточки товара к иконке корзины).
- Кнопка «наверх» (Back To Top).
- Функция «поделиться» товаром (Share API / соцсети).
- Toast-уведомления.

## 4. Backend API (`FlowerShop.API`)

### 4.1 Архитектура и стек

Clean Architecture, 4 слоя:

```
FlowerShop.Domain          — сущности, enum'ы, доменная логика без внешних зависимостей
FlowerShop.Application     — DTO, интерфейсы сервисов, валидация (FluentValidation)
FlowerShop.Infrastructure  — EF Core (Npgsql), реализации сервисов, миграции
FlowerShop.API             — контроллеры, middleware, Program.cs, Swagger
```

Ключевые библиотеки: EF Core 9.0.5 + Npgsql 9.0.4, FluentValidation 11.x, JWT Bearer 9.0.5, SixLabors.ImageSharp 3.1.10 (ресайз/конвертация изображений в WebP), Serilog (консоль + файл, ротация по дням), Swashbuckle (Swagger с Bearer-схемой).

> Примечание: MediatR и AutoMapper **не используются** — доступ к `AppDbContext` напрямую из сервисов/контроллеров, маппинг DTO вручную.

### 4.2 Сквозная функциональность
- Глобальная обработка исключений — `GlobalExceptionHandlingMiddleware`.
- CORS — по белому списку `AllowedOrigins` из конфигурации.
- Rate limiting: `otp` — 5 запросов/час, `api` — 100 запросов/мин (фиксированные окна).
- Автомиграция БД и сидирование стартовых данных (`DatabaseSeeder`) при запуске приложения.
- Swagger UI с поддержкой Bearer-авторизации для тестирования API.

### 4.5 Ключевые сервисы бизнес-логики

- **AuthService** — генерация/проверка OTP, выпуск JWT (access + refresh) и ревокация токенов при выходе.
- **OrderService** — создание заказа со снапшотом товаров/аддонов в JSON (защита от изменения цен «задним числом»), генерация номера заказа, ведение истории статусов, начисление/списание баллов лояльности при заказе, отмена заказа.
- **PricingService** — расчёт итоговой стоимости: праздничная наценка, стоимость доставки (бесплатно от порога), скидка по промокоду, скидка за счёт баллов лояльности (с ограничением максимального процента списания).
- **LoyaltyService** — начисление баллов (доля от суммы заказа), списание и пересчёт тира клиента.
- **LocalFileStorageService** — сохранение загружаемых файлов на диск, ресайз изображений (макс. 600×800) и конвертация в WebP через ImageSharp, раздача статики по пути `/uploads`.
- **MockSmsService / EskizSmsService** — отправка SMS с OTP-кодом (mock — пишет в лог; Eskiz — см. раздел 8, не реализовано полностью).

### 4.6 Аутентификация и безопасность
- JWT (HMAC-SHA256), access-токен — 15 минут, refresh-токен — 30 дней.
- Refresh-токены хранятся в БД в виде SHA-256 хеша, с возможностью ревокации.
- Роль покупателя передаётся как JWT-claim `customer`.
- Rate limiting на OTP и общий API (см. 5.2).

### 4.7 Хранение файлов
- Заявлено (docker-compose): MinIO (S3-совместимое объектное хранилище).
- Фактически реализовано: локальное файловое хранилище на диске контейнера API (`FileStorage:BasePath`, том `uploads_data`), обработка изображений через ImageSharp с конвертацией в WebP.

### 4.8 Миграции базы данных (история)

1. `InitialCreate` — базовая схема (вся доменная модель).
2. `FixLoyaltyTransactionFK` — исправление внешнего ключа `LoyaltyTransaction`.
3. `AddPasswordHashToUser` — историческая миграция; поле не используется активной функциональностью после удаления административного контура.

## 7. Известный технический долг и незавершённые задачи

Зафиксировано по факту анализа кода на дату составления документа — требует решения перед выводом в продакшн:

1. **MinIO не используется в коде.** Сервис поднимается в docker-compose, но backend работает с локальной файловой системой. Требуется либо реализовать интеграцию (`Infrastructure/Services`, заменить `LocalFileStorageService` на MinIO-based реализацию `IFileStorageService`), либо убрать сервис MinIO из инфраструктуры как неиспользуемый.
2. **Интеграция с Eskiz SMS не завершена** — `EskizSmsService` содержит `TODO` вместо реального HTTP-вызова к `https://notify.eskiz.uz/api`. В продакшене SMS реально не отправляются.
3. **Секреты в конфигурации.** `appsettings.json` содержит заглушку `Jwt:SecretKey` и пример пароля БД в строке подключения — необходимо вынести в переменные окружения/секрет-хранилище перед продакшеном.
4. **Изображения-заглушки каталога.** Frontend использует моковые данные (`entities/product/mock.ts`) с изображениями Unsplash, часть которых визуально не соответствует названиям товаров (задокументировано отдельно в `TASK_IMAGES.md` внутри `flower-shop` — требуется замена ID изображений и добавление `onError`-fallback на `/placeholder-flower.svg`).
5. **Платёжные интеграции** (Душанбе Сити, Alif) — в модели данных заложены, но по коду фактическая интеграция с внешними платёжными шлюзами не обнаружена.
