# ТЗ: Исправление изображений товаров (несоответствие фото и названия)

## Контекст

Файл с данными товаров: `flower-shop/src/entities/product/mock.ts`.
Изображения берутся напрямую с CDN Unsplash по фиксированным ID через хелпер:

```ts
const U = (id: string) =>
  `https://images.unsplash.com/photo-${id}?w=600&h=800&fit=crop&auto=format&q=80`

const IMG = {
  peony:  [...], rose: [...], tulip: [...], daisy: [...],
  mixed:  [...], white: [...], exotic: [...], garden: [...],
}
```

Каждый товар в `MOCK_PRODUCTS` ссылается на 2 картинки из этих массивов (`images: [IMG.rose[0], IMG.rose[1]]` и т.д.), при этом индексы переиспользуются между разными товарами. Из-за этого один "плохой" ID ломает сразу несколько карточек.

## Требования к решению

1. **Источник изображений** — только легальные CDN без скрейпинга сторонних цветочных сайтов:
   - Unsplash (`images.unsplash.com/photo-{id}`) — используется сейчас, оставить как основной вариант.
   - Pexels (`images.pexels.com/photos/{id}/pexels-photo-{id}.jpeg`) — годный запасной источник, не требует API-ключа для хотлинка на CDN.
   - Pixabay — доступен только через официальный API (нужен `PIXABAY_API_KEY`, которого сейчас нет в `.env`); использовать при наличии ключа.
2. **Каждый ID подбирается по названию/составу товара** и **визуально проверяется перед коммитом** (скачать превью → посмотреть → только потом вставить в `mock.ts`). Метод, которым уже пользовались в этой сессии, полностью рабочий: `curl` на CDN без ключа + просмотр через Read.
3. Разбить общий `IMG` на более узкие категории вместо переиспользования 2–3 картинок на 6+ товаров разного цвета/состава, например:
   `roseRed`, `rosePinkMix`, `roseWhite`, `peonyPink`, `peonyWhite`, `tulipMixed`, `tulipPurpleSingle`, `tulipYellow`, `springMix`, `wildflowerMeadow`, `driedFlowers`, `gardenMixPremium`, `chamomileDaisy`, `chrysanthemumWhite`, `hydrangeaGarden`, `exoticTropical`, `classicWhiteBouquet`, `funeralWhite`.
4. **Единый аспект-рейтио и качество** — сохранить текущий паттерн `?w=600&h=800&fit=crop&auto=format&q=80` (соотношение 3:4) для всех URL, включая новые источники (Pexels: аналогичные query-параметры `?auto=compress&cs=tinysrgb&w=600&h=800&fit=crop`).
5. **Fallback при ошибке загрузки** — добавить обработку `onError` в компоненте карточки товара (`ProductCard`, см. `flower-shop/dist/assets/ProductCard-A_OCaioC.js` → искать исходник в `src/`), подставляющую локальный placeholder (например `/placeholder-flower.svg`), чтобы битый URL не показывал "сломанную картинку" браузера.
